# Dev Setup

Use a managed Python environment and install ESPnet from the checkout you edit.
The supported Python range is declared in `pyproject.toml`: currently Python
3.12 or 3.13 (`>=3.12,<3.14`). Python 3.11 does not satisfy this checkout.

## Create a Pixi environment

After installing Pixi, clone ESPnet and enter the repository:

```bash
git clone https://github.com/espnet/espnet.git
cd espnet
pixi init
pixi add python=3.12 pip uv ffmpeg
pixi shell
```

If a Pixi manifest already exists, use its environment rather than initializing
another one. For a shell script, `eval "$(pixi shell-hook)"` activates it.
Avoid `set -u` around environment activation hooks that read unset shell variables.

Add non-Python tools required by your recipe with `pixi add`, for example
`pixi add sox cmake`. A virtual environment managed another way is also supported;
ESPnet's Python packaging does not require Pixi.

## Install development dependencies

```bash
uv pip install -e ".[train,asr,test]"
```

`train` supplies the Lightning/Dask training stack; `asr` supplies ASR-specific
extras; `test` supplies test tools. A plain `pip install -e .` installs the base
inference dependencies and is not a complete training/test environment.
Use the extras declared by `pyproject.toml` for other tasks, for example:

```bash
uv pip install -e ".[train,tts,test]"
uv pip install -e ".[doc]"
```

Choose a supported PyTorch build for your CPU/CUDA environment and check
`ci/image_variants.json` and `tools/installers/install_torch.sh` before changing
versions. Do not assume arbitrary torch/torchaudio versions are interchangeable.

To select the active interpreter explicitly:

```bash
uv pip install -e ".[train,asr,test]" --python "$(command -v python)"
```

## Recipe tools

Some recipes need tools from `tools/installers/`. Read the recipe README and the
installer before running it. For example, Mini-AN4 preparation needs `sph2pipe`.
Activate the intended environment first and verify `python -m pip --version`;
installers may use `pip` or build native binaries rather than use `uv`.
Do not rewrite shared installer scripts solely to change package managers.

`tools/activate_python.sh` is generated by the tools setup; a manually managed
Pixi environment does not automatically create it. Python examples can run from
an activated environment. CI shell scripts that source this file additionally
require the tools setup described in `CONTRIBUTING.md`.

## Verify imports and run focused checks

```bash
python -c "import espnet3"
python -c "from espnet3.systems.esp2_asr.system import ASRSystem"
python -c "from espnet3.systems.launch import launch"
ffmpeg -version
pytest -q test/espnet3/systems/esp2_asr/
```

The package's editable install must resolve to the checkout you intend to test.
When using multiple worktrees, check module locations instead of replacing an
editable install used by another job:

```bash
python -c "import espnet3; print(espnet3.__file__)"
```

Run the repository CI scripts for broader verification; see
[CI and PR](./ci-and-pr.html). Report the Python version, installation command,
active interpreter and full traceback when requesting help.
